## 2. 세부 컴포넌트 아키텍처 및 핵심 엔진

### 2.1 독립 마이크로서비스(MSA) 분리 및 이벤트 기반 파이프라인
* **`dedup-service` (중복 정제 전담 마이크로서비스)**:
  - **책임**: CPU 집약적인 텍스트 유사도 연산(`SimHash 64-bit` 해싱 및 상위 키워드 `Jaccard 75%` 교차 비교).
  - **이벤트 흐름**: `raw-jobs-stream` 컨슘 ➔ 단일 고유 공고 병합 ➔ `deduped-jobs-stream`으로 프로듀스.
  - **격리 이점**: AI 연산 병목과 무관하게 초당 수천 건의 원시 스크래핑 데이터를 지연 없이 중복 제거.
* **`ai-enrichment-service` (AI 지능형 정제 마이크로서비스)**:
  - **책임**: 외부 LLM 네트워크 I/O 집약적 멀티 에이전트(Agent 1 스택, Agent 2 복지, Agent 3 교차검증) 오케스트레이션.
  - **이벤트 흐름**: `deduped-jobs-stream` 컨슘 ➔ Token Bucket 통과 ➔ 3단계 정제 ➔ `enriched-jobs-stream` 프로듀스.
  - **수평 확장(HPA)**: 채용 시즌 공고 폭증 시 K8s / Docker Compose 상에서 워커 인스턴스만 2개에서 10개로 독립 스케일아웃.

### 2.2 컨테이너 무중단 배포 및 메시지 큐 안전성 (Graceful Shutdown & Manual Offset Commit)
* **Kafka Consumer 수동 오프셋 커밋 (`enable.auto.commit = false`)**:
  - 컨테이너가 갑자기 종료되거나 재부팅될 때 처리 중이던 메시지의 유실(Data Loss)이나 중복 소비를 원천 차단.
  - DB 또는 다음 토픽으로의 적재 트랜잭션이 완벽히 성공한 직후에만 `consumer.commit_sync()`를 명시적으로 호출.
* **무중단 Graceful Shutdown 수명 주기**:
  ```python
  # 컨테이너 종료 시그널(SIGTERM / SIGINT) 처리 로직
  def sigterm_handler(signum, frame):
      logger.info("SIGTERM 수신: 신규 메시지 폴링 중단 및 처리 중인 배치 완료 대기...")
      consumer.pause() # 신규 메시지 수신 즉시 중단
      process_current_in_flight_messages() # 메모리 내 진행 중 작업 완수
      consumer.commit_sync() # 최종 오프셋 안전 커밋
      consumer.close()
      sys.exit(0)
  ```
  - Docker Compose 롤링 업데이트 시 최대 30초(`stop_grace_period: 30s`)의 유예 시간을 부여하여 작업 중단 없는 무중단 배포 실현.

### 2.3 폐쇄망 관제 및 알림 보안 (Security Compliance: Mattermost / Zulip Webhook)
* **`AlertWebhookService` (플러그형 멀티 채널 경보)**:
  - 금융권 및 엔터프라이즈 보안 정책상 서버 IP, DB 커넥션 오류 등 민감 인프라 로그가 퍼블릭 메신저로 전송되는 위험 차단.
  - **사내 설치형 메신저(Mattermost / Zulip) Webhook 1순위 채택**: 사내 폐쇄망(VPC) 내 구축된 협업 메신저로 실시간 에러 마크다운 전송.
  - **모바일 긴급 채널**: 외부 이동 중인 관리자를 위해 마스킹된 요약 알림(민감 IP 제외)만 Telegram Bot API로 이중화 발송.

### 2.4 무결점 Zero-Trust 검증 (Anti-Fraud 4단계 파이프라인)
* **`apps/web/services/zero_trust_verifier.ts`**:
  - 합격 축하금(50만 원) 부정 수급을 차단하기 위한 단계별 무결점 방어선:
    1. **1단계 (악성코드 방어)**: `ClamAV`를 통한 PDF/JPG 악성 익스플로잇 스캔.
    2. **2단계 (포토샵 메타데이터 검증)**: `ExifTool`을 통한 레이어 수정 흔적, `Photoshop/Canva` 수정 소프트웨어 태그 자동 탐지.
    3. **3단계 (이미지 OCR 직인 대조)**: 건강보험공단 직인, 16자리 발급번호, 취득 사업장명, 자격취득일 OCR 추출 대조.
    4. **4단계 (공인 마이데이터/정부24 스크래핑 API 직통 연동 - Machine-to-Machine)**:
       - 이미지 파일 자체의 교묘한 픽셀 단위 위조 리스크를 완전히 제거.
       - 지원자의 간편인증(카카오/PASS) 동의를 기반으로 국민건강보험공단 자격득실확인 DB를 실시간 스크래핑/마이데이터 API로 직접 조회하여 사업장명과 입사일이 100% 일치하는지 전산상으로 즉시 대조.

### 2.5 불변 스토리지 및 법정보관 데이터 자동 파기 (AWS S3 Object Lock WORM & Lifecycle)
* **`CompanySubmittedArchive` (채용절차의 공정화에 관한 법률 제11조 준수)**:
  - 구직자 탈퇴 시 개인 프로필은 30일 후 영구 삭제(Hard Delete)되나, **기업에 이미 제출 완료된 지원서는 3년간 법정 의무 보관**.
  - **S3 Object Lock (WORM: Write Once, Read Many / Compliance Mode)** 적용:
    - Root 계정이나 최고 관리자라도 3년 보존 기간(`Retention Period = 3 Years`) 내에는 파일 삭제, 덮어쓰기, 변조가 불가능하도록 암호학적으로 강제.
  - **S3 Lifecycle 정책을 통한 자동 물리 파기**:
    - 보존 기간(1,095일) 만료 즉시 AWS 수명 주기 규칙에 의해 추가 수동 작업 없이 파일이 물리적으로 영구 파기(Crypto-shredding)되어 규제 감사 100% 통과.

### 2.6 AI 토큰 버킷 큐잉 레이어 (Redis Token Bucket Rate Limiter)
* **`crawlers/pipeline/llm_rate_limiter.py`**:
  - 하루 수만 건 공고 동시 유입 시 외부 LLM API(OpenAI/Anthropic)의 TPM(분당 토큰) 및 RPM(분당 요청) 한도 초과(`HTTP 429`) 원천 방어.
  - Kafka `deduped-jobs-stream`과 AI 에이전트 사이에 Redis 해시 기반 **Token Bucket / Leaky Bucket**을 배치하여 토큰이 확보된 경우에만 분석 워커가 메시지를 소비하고, 한도 도달 시 지수 백오프로 무중단 대기.

### 2.7 커뮤니티 신고 역어뷰징 방어 (신고자 신뢰도 가중치 시스템)
* **`apps/web/services/community_guard.ts`**:
  - 경쟁사나 특정 집단의 조직적 허위 신고로 정상 리뷰가 가려지는 취약점 방어.
  - **신고자 신뢰도 가중치(Reputation Weight)**: 신규 계정 `0.3`, 일반 활동 계정 `1.0`, 인증 현직자 `1.5`, 허위 신고 이력자 `0.0`.
  - 가중치 합계 **`5.0 이상`** 도달 시에만 자동 블라인드(`is_blinded = 1`).
  - 10분 내 동일 IP 대역 집중 신고 감지 시 서킷 브레이커가 발동하여 블라인드를 보류하고 관리자 AG Grid 심사 큐로 격리.

### 2.8 고트래픽 행 잠금 및 봇넷 조작 방어: Redis Write-Back & Cloudflare Turnstile
* **`apps/web/services/view_counter.ts` & `workers/counter_flush.ts`**:
  - Cloudflare Turnstile(비가시적 캡차)과 Edge Rate Limiting(초당 5회 이상 차단)으로 봇넷 어뷰징 차단.
  - Redis `INCR` 및 24시간 중복 방지 키로 인메모리 버퍼링 후 3~5분 주기로 RDBMS에 배치 동기화.

### 3.4 ATS 지원자 전형 상태 변경 및 불변 감사 원장 API
* `PATCH /api/ats/applications/[id]/stage`:
  * Request: 
    ```json
    { 
      "stage": "DOC_PASS" | "INTERVIEW" | "FINAL_OFFER" | "REJECTED" | "WITHDRAWN", 
      "changeReason": "1차 기술 면접 합격에 따른 최종 임원 면접 전환",
      "withdrawalReason": "구직자 타사 최종합격으로 인한 자진 포기"
    }
    ```
  * Transaction: `candidate_applications` UPDATE + `application_history` 불변 감사 원장 INSERT (ACID 단일 트랜잭션).
